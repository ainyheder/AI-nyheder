Wiz Research hackede Snowflakes Jira via AI-kode

Wiz Research's AI-sikkerhedsværktøj fandt og udnyttede et hul i Snowflakes GitHub-workflow, der blev introduceret med AI-genereret kode. Hullet blev lukket samme dag.

Sårbarheden

Wiz Research's autonome AI-værktøj 'Red Agent' fandt et hul i et af Snowflakes offentlige GitHub-repositorier. Hullet gjorde det muligt for enhver at køre kommandoer på GitHub Actions ved at åbne en issue med et særligt udformet titelfelt. Problemet opstod, da en AI-assisteret kodeændring blev flettet ind i projektet.

AI-koden fejlede

GitHub Copilot's 'Autofix' godkendte ændringen som sikker, og GitHub Advanced Security-scannere opdagede ikke hullet. Wiz Red Agent udnyttede dog hullet og fik adgang til Snowflakes Jira-credentials med læseadgang til hele virksomhedens projektstyring. Hele processen fra opdagelse til eksfiltrering tog kun få sekunder.

Lukket samme dag

Snowflake fik besked den 23. juni og lukkede hullet samme dag ved at rulle den usikre kode tilbage og rotere credentials. Wiz bekræftede, at de var de eneste, der havde adgang i de fem dage, hullet var åbent. Begge parter understreger nu vigtigheden af at kontrollere AI-genereret kode lige så grundigt som menneskeskrevet kode.

Detaljerne
  • Wiz Red Agent er et autonomt AI-drevet sikkerhedsværktøj til forskning.
  • Hullet blev fundet i snowflakedb/snowflake-connector-net på GitHub.
  • GitHub Copilot Autofix havde godkendt koden som sikker, men overså hullet.
  • Wiz fik adgang til Snowflakes Jira med læseadgang til følsomme projekter.
  • Sårbarheden blev introduceret via PR #1218, der blev flettet den 18. juni.
  • Snowflake lukkede hullet og roterede credentials samme dag som anmeldelsen.
  • GitHub Advanced Security-scannere opdagede ikke den kritiske injektion.
Hvad betyder det for dig?
Du kan ikke stole blindt på AI-genereret kode eller automatiske sikkerhedstjek - selv store virksomheder som Snowflake kan blive ramt, hvis de ikke laver manuel gennemgang.
